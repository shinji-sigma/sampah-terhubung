Baseline: commit lokal `8f1d1ff`, branch `codex/sampah-terhubung-local`. Revisi menerapkan permintaan pengguna pada aplikasi yang sama. PRD, riset, desain sumber, Personal AI, API, autentikasi, migrasi/RLS, dependency, dan favicon dipertahankan. Tidak ada push atau publikasi.

## Keputusan dan perubahan

- Beranda dimulai dengan **Wilayah Saya** dan nama wilayah utuh. Jadwal terdekat menjadi informasi utama; satu aksi pelaporan mengikuti ketersediaan autentikasi/layanan. Hero, orbit dan kartu ajakan berulang dihapus. Cakupan menjadi kolom pendukung desktop, setelah kebutuhan utama di ponsel.
- Logo asli SHINFRAME digunakan utuh: 184 px desktop dan 150 px ponsel, rasio 3:1, latar terang. Nama produk tetap Sampah Terhubung. Salinan `public/brand/shinframe.png` memiliki SHA-256 yang sama dengan aset pengguna: `04E3A152D0E11432CDFE899CC58728AB6F7A5200BB2FD66AEB5855BF85900C8C`. Aset ikut clone laptop kedua; tidak perlu menyalin folder eksternal.
- Jadwal menjadi baris tanggal/waktu, layanan/cakupan, dan status. Sumber, konfirmasi, masa berlaku dan pembaruan tersedia per aturan melalui detail keyboard. Periode menggunakan nama bulan Indonesia; input date tetap ISO. Ringkasan mencari dua layanan terdekat dalam periode 14 hari, sehingga jadwal mingguan yang lebih dari tiga hari tidak hilang.
- Penanganan menjadi daftar lokasi/status/referensi. Preview kini membedakan `#4000-00000001` dan `#4000-00000002`; prefix diperpanjang bila diperlukan, tanpa mengubah UUID. UUID lengkap tetap tersedia pada detail. Riwayat, petugas, kendala dan bukti ditampilkan hanya dari data yang tersedia untuk akun. Proyeksi publik tidak memiliki riwayat pembaruan status; timestamp diberi label **Validasi**, bukan diklaim sebagai pembaruan terakhir.
- Pemilih wilayah memakai pencarian/daftar di kiri dan peta di kanan pada desktop. Ponsel menampilkan daftar lebih dahulu. GPS tetap tindakan opsional; daftar manual dan atribusi peta tetap tersedia.
- Kegiatan kosong memberi penjelasan singkat dan tautan ke jadwal. Kegiatan berisi diperiksa memakai fixture MOCK terisolasi. Nama, waktu, lokasi, PIC, alat/tugas dan konfirmasi pengangkutan terlihat; persyaratan publikasi tetap mengikuti backend.
- Antrean koordinator, tugas petugas dan formulir menggunakan tipografi, jarak dan batas baris yang sama. Tugas aktif didahulukan lalu diurutkan menurut perkiraan tindak lanjut. Bidang wajib dan transisi status dipertahankan. Menu ponsel mendukung Escape dan mengembalikan fokus ke tombol navigasi.

## Pemeriksaan yang dijalankan

Lint, typecheck, build produksi, dan **26/26 tes lokal** lulus. Dua tes tambahan memeriksa referensi insiden yang tidak bertabrakan dan format tanggal metadata. Tes PostgreSQL tetap PGlite terisolasi, bukan Supabase Cloud.

Browser produksi baru: **0 error, 0 warning** pada preview. Tidak ada overflow horizontal pada halaman publik dan tiga keadaan peran yang diperiksa di kedua viewport. Logo memiliki dimensi asli 2172 × 724 dan rasio tampilan 3:1. Pada beranda ponsel, tanggal dan jam layanan pertama selesai tampil sekitar y=510 px, di dalam layar awal 800 px. Nama wilayah preview tampil utuh. Metadata beranda minimum 14 px; tombol aktif yang terlihat memiliki tinggi sekurangnya 44 px.

Menu Escape mengembalikan fokus; Enter membuka detail sumber dan UUID lengkap. Input tanggal terbaca sebagai `2026-10-09`; periode tampil `9 Oktober 2026 – 22 Oktober 2026`. Pencarian/pilihan wilayah memakai keyboard berhasil saat tile gagal dan izin GPS disimulasikan ditolak. Form petugas memperlihatkan error kolom, mempertahankan isian setelah command gagal, menonaktifkan submit selama loading, dan menampilkan pesan berhasil yang secara eksplisit berlabel **SIMULASI UI — tidak disimpan ke backend**. Respons sukses tersebut hanya berasal dari alat pengujian pada dev harness; tidak ditambahkan ke backend/preview produksi.

Produksi: `/ui-test` HTTP **404**, `/api/public` **503** ketika konfigurasi belum tersedia, `/icon.svg` **200**. Lima hash dokumen sumber dan hash logo diperiksa kembali. Log pemeriksaan DOM: [public-check](../output/playwright/design-revision/public-check.log), [navigation-check](../output/playwright/design-revision/navigation-check.log).

## Mengulang dan batas verifikasi

Jalankan `npm run build` lalu `npm start -- --port 3001`, dan buka `/preview`. Skrip CLI berada di `output/playwright/capture-public-after.js` dan `check-navigation-after.js`; session Chrome baru menghindari route kegagalan dari skenario sebelumnya. Untuk peran: jalankan `npx tsx scripts/ui-fixtures.ts`, mulai dev port 3002 dengan `ALLOW_UI_FIXTURES=true`, gunakan `mock-coordinator.js` / `mock-worker.js` / `mock-reporter.js`, lalu `capture-role-after.js`. Periksa snapshot sebelum tindakan, sesuai skill Playwright.

Konfigurasi diperiksa hanya melalui boolean: URL, publishable key, kunci server dan password demo **belum tersedia**. Auth, database, unggahan foto dan akses dengan Supabase Cloud sungguhan serta sinkronisasi laptop kedua masih menunggu konfigurasi pemilik. Panduan tetap [SUPABASE_CLOUD.md](SUPABASE_CLOUD.md), dengan lokasi clone `D:\WebDemo` dan tanpa persyaratan Docker. Pengujian ini bukan audit screen reader lengkap atau pengukuran kinerja Cloud.
